## TL;DR

| Question | Answer |
|---|---|
| Can we post user reviews or ratings to **IMDb** programmatically? | **No. There is no legitimate route.** The official IMDb API is read-only, enterprise-priced, and licensed through AWS Data Exchange. IMDb's Conditions of Use ban robots and scraping without written consent. The most we can do is a manual assist: copy the review to the clipboard and deep-link the user to the IMDb title page. |
| Can we use IMDb's free datasets to power a public site? | **Not as our catalogue.** They are licensed for "personal and non-commercial use" only, and must not be "republished … to create any kind of online/offline database of movie information". A public catalogue site is exactly that. Engineers may use them for offline prototyping or analysis only. |
| Best primary catalogue source | **TMDB API.** It is free for non-commercial use with attribution, covers movies and TV, has images and reviews, supports `discover` filters for rating and vote-count floors, and has generous limits (about 40–50 requests per second per IP). |
| Is outbound review sync realistic anywhere? | **Trakt** is the only mainstream service that accepts full review text (comments), plus ratings and watch history. Since August 2026, though, creating a Trakt API app needs a Trakt VIP account (about $60 a year), and free Trakt users can connect only one app. **TMDB** accepts ratings through its API but not reviews. **Simkl** accepts history and ratings and is free. **Letterboxd**'s API is closed to apps like ours, but its **CSV import** works, so a "Letterboxd-format export" is a realistic hand-off. |
| IMDb rating display | IMDb ratings can be shown through **OMDb** (`imdbRating`, 1,000 requests a day free, CC BY-NC data). It must be labelled and attributed, and cached server-side. It is a secondary badge, not the filter source. |
| Free hosting | **Vercel Hobby** is fine for a non-commercial MVP but bans commercial use. **Cloudflare Pages** allows commercial use on its free tier. **Supabase Free** gives 500 MB, 50k MAU, and pauses after 7 days idle. **Neon Free** gives 0.5 GB and scales to zero without pausing the project. |

## 1. IMDb

### 1.1 Official IMDb API (AWS Data Exchange)
- Available only through AWS Data Exchange / AWS Marketplace, as a GraphQL API. You need an AWS account and a subscription contract. [developer.imdb.com](https://developer.imdb.com/) · [getting access](https://developer.imdb.com/documentation/api-documentation/getting-access/) · [AWS Marketplace listing](https://aws.amazon.com/marketplace/pp/prodview-wdqq4hg3bcbws) · [IMDb Help: Introducing the IMDb API](https://help.imdb.com/article/imdb/general-information/introducing-the-imdb-api/G49M5Y59L5N4WABM)
- Pricing is not public. Third-party reporting puts entry-level pricing at roughly **$150,000 a year plus metered charges**, and a 1-month free trial exists. (verify) [api.market blog](https://api.market/blog/sleeyax/entertainment/best-movie-apis) · [dev.to comparison](https://dev.to/zuplo/whats-the-best-movie-database-api-imdb-vs-tmdb-vs-omdb-b24)
- **It has read-only contracts with no write operations.** There is no endpoint to submit ratings, reviews, check-ins, or watchlist items. [apis.io IMDb profile](https://apis.io/providers/imdb-api/)
- Verdict: unaffordable for a free-tier MVP, and useless for writing anyway.

### 1.2 Posting reviews or ratings to IMDb — honest feasibility
- IMDb reviews and ratings are entered **manually on imdb.com or in the IMDb app**. [IMDb Help: add my film reviews](https://origin-help.imdb.com/article/imdb/track-movies-tv/how-do-i-add-my-film-reviews-to-the-site/GMC7JNM7JWZ4WKWL) · [IMDb Ratings FAQ](https://help.imdb.com/article/imdb/track-movies-tv/ratings-faq/G67Y87TFYYP6TWAV)
- IMDb **Conditions of Use** prohibit "data mining, robots, screen scraping, or similar data gathering and extraction tools" without express written consent. Automating a logged-in IMDb session (headless browser, cookie replay) to post on a user's behalf would breach these terms. It would also risk getting both the user's account and our IPs banned, and would mean handling users' IMDb or Amazon credentials. **We will not build this.** [IMDb Conditions of Use](https://www.imdb.com/conditions/)
- Community tools that "sync to IMDb" (for example IMDBTraktSyncer on PyPI) work by driving the user's own browser session. They are personal-use scripts in a grey area and are not an option for a public product. [pypi IMDBTraktSyncer](https://pypi.org/project/IMDBTraktSyncer/1.8.7)
- IMDb **does** let users export their own ratings, watchlist and lists as CSV, on desktop only. There is **no import**. [Listy: export IMDb](https://listy.is/import/imdb/) · [IMDb community: export](https://community-imdb.sprinklr.com/conversations/imdbcom/ratings-export-in-csv-file/642d284919cfd465229b3785)
- IMDb has "Watched", check-ins and ratings features, which make it a direct competitor, but it is closed. [IMDb Watched FAQ](https://help.imdb.com/article/imdb/new-features-updates/mark-as-watched-faq/GR2SD7Y4LZVNHUVH) · [Check-ins FAQ](https://help.imdb.com/article/imdb/track-movies-tv/check-ins-faq/GG59ELYW45FMC7J3)

**Verdict: writing reviews or ratings "directly to IMDb" is not possible legitimately for a third-party app, at any price tier.** The acceptable UX is **"Also post on IMDb"**: copy the review text to the clipboard, then open the title's IMDb page (`https://www.imdb.com/title/{tt-id}/`) in a new tab, where the user pastes the text and submits it. Don't hard-code IMDb's internal review-form URLs, because they change. We mark the review as "shared to IMDb (manual)" only when the user confirms. IMDb IDs come from TMDB's `external_ids`.

### 1.3 IMDb non-commercial datasets
- Files at `https://datasets.imdbws.com/`, gzipped UTF-8 TSV, **refreshed daily**. There are 7 files: `name.basics`, `title.akas`, `title.basics`, `title.crew`, `title.episode`, `title.principals`, `title.ratings`. [IMDb non-commercial datasets](https://developer.imdb.com/non-commercial-datasets) · [schema notes](https://zindilis.com/posts/imdb-non-commercial-datasets-schema/)
- `title.basics` holds tconst, titleType (movie, tvSeries, tvMiniSeries …), primaryTitle, originalTitle, isAdult, startYear, endYear, runtimeMinutes and genres. `title.ratings` holds tconst, averageRating and numVotes. It has **no posters, plots or reviews**.
- Size: `title.basics.tsv.gz` is about 90 MB compressed, and `title.ratings` has well over 1M rows. [GitHub mirror](https://github.com/unqueued/datasets.imdbws.com-dataset/blob/master/title.basics.tsv.gz) · [Medium EDA](https://medium.com/analytics-vidhya/exploratory-data-analysis-imdb-dataset-cff0c3991ad5)
- **Licence**: "personal and non-commercial use". The data "must not be altered/republished/resold/repurposed to create any kind of online/offline database of movie information (except for individual personal use)". Attribution: "Information courtesy of IMDb (https://www.imdb.com)". IMDb can withdraw permission at any time. [IMDb Help: Can I use IMDb data in my software?](https://help.imdb.com/article/imdb/general-information/can-i-use-imdb-data-in-my-software/G5JTRESSHJBBHTGX)
- **Verdict**: a public catalogue website, even a non-commercial one, is an "online database of movie information", so using the datasets as our catalogue would breach the licence. Allowed uses: internal analysis, choosing the threshold, and QA cross-checks. Not allowed: serving IMDb ratings to the public from the dump.

## 2. TMDB (The Movie Database) — recommended primary source

- **Terms**: free for non-commercial use with attribution. Show the notice *"This product uses the TMDB API but is not endorsed or certified by TMDB."* with the TMDB logo in an About or Credits section. Do not cache TMDB content for longer than **6 months**. [TMDB API Terms of Use](https://www.themoviedb.org/api-terms-of-use) · [TMDB FAQ](https://developer.themoviedb.org/docs/faq)
- **Commercial**: once we add ads, subscriptions, or charge users, we need a commercial licence. It is reported at **$149/month for companies under $1M revenue**; above that, pricing is negotiated. (verify) [TMDB API for Business](https://www.themoviedb.org/api-for-business) · [TMDB talk: ads need commercial?](https://www.themoviedb.org/talk/68064474276bf64e41aace48) · [api.market](https://api.market/blog/sleeyax/entertainment/best-movie-apis)
- **Rate limits**: the legacy limit of 40 requests per 10 seconds was disabled on 2019-12-16. Soft upper limits of about **40–50 requests per second per IP** remain, plus a CDN cap of about 20 connections per IP. There is no daily cap, and developer and commercial keys get the same limits. [TMDB rate limiting](https://developer.themoviedb.org/docs/rate-limiting) · [go-tmdb issue](https://github.com/ryanbradynd05/go-tmdb/issues/44) · [TMDB talk](https://www.themoviedb.org/talk/686cff2fb5eabfc4219a459e)
- **Discover** (`/3/discover/movie`, `/3/discover/tv`):
  - Filters include `vote_average.gte`, `vote_count.gte`, `primary_release_date.gte/lte` (movie), `first_air_date.gte/lte` (tv), `with_genres`, `with_original_language`, and `watch_region` + `with_watch_providers`. Comma means AND and pipe means OR. [TMDB talk: sort by rating](https://www.themoviedb.org/talk/56d5ef6ec3a3681e3c019e43) · [R TMDb discover_movie](https://search.r-project.org/CRAN/refmans/TMDb/html/discover_movie.html) · [R TMDb discover_tv](https://search.r-project.org/CRAN/refmans/TMDb/html/discover_tv.html)
  - `sort_by` for movies: `popularity`, `vote_average`, `vote_count`, `primary_release_date`, `revenue`, `title` (`.asc` or `.desc`). For TV: `popularity`, `vote_average`, `first_air_date`, `name`, `vote_count`.
  - Pages are limited to 20 results each and **page ≤ 500**, so one query returns at most about 10,000 results. We must shard by year or date range to ingest more. (verify)
  - Gotcha: sorting by `vote_average.desc` without a `vote_count.gte` floor surfaces obscure titles with 1–5 votes. TMDB's own "Top Rated" list uses a floor of about 200 votes for movies. [TMDB top rated reference](https://developer.themoviedb.org/reference/movie-top-rated-list) · [TMDB talk: discovery sorting issues](https://www.themoviedb.org/talk/62ad4370bb10570061fbcbaa)
- **Scale**: about 1.39M movies, 234k TV shows and 6.7M episodes (FAQ snapshot). [TMDB general FAQ](https://www.themoviedb.org/faq/general)
- **TV support**: full, covering series, seasons, episodes, `external_ids` (IMDb tconst), reviews, videos, images and `watch/providers`.
- **Reviews (read)**: `/movie/{id}/reviews` and `/tv/{id}/reviews` return TMDB community reviews (often few per title). We can show these as "Community reviews from TMDB", attributed.
- **Account write support**: with a v3 `session_id` (TMDB user login via request-token flow) or a v4 user access token, a user can **rate** movies, TV shows and episodes (0.5–10), and manage their watchlist, favourites and lists. Guest sessions can rate too. [TMDB user auth](https://developer.themoviedb.org/docs/authentication-user) · [TMDB talk: rate requires session_id](https://www.themoviedb.org/talk/5db2c7f74b0c630017ea74d8)
- **Reviews (write): not supported through the API.** Users must write reviews on the TMDB website. [TMDB talk: API to post reviews](https://www.themoviedb.org/talk/61af7758699fb70088a3e0d1) · [TMDB talk: write review API](https://www.themoviedb.org/talk/61231a96a1d3320044d482fb)
- **Watch providers**: `/movie/{id}/watch/providers` and `/tv/{id}/watch/providers` give per-country flatrate, rent and buy data, powered by **JustWatch**. JustWatch must be attributed wherever the data appears. [TMDB watch providers](https://developer.themoviedb.org/reference/movie-watch-providers) · [TMDB talk: attributing JustWatch](https://www.themoviedb.org/talk/60355e30a284eb003da676f2)

## 3. OMDb
- It has a free key with **1,000 requests per day**. Patreon tiers (from about $1/month) raise quotas and unlock the Poster API. Responses include `imdbRating`, `imdbVotes`, and a `Ratings[]` array (IMDb, Rotten Tomatoes, Metacritic). [omdbapi.com](http://www.omdbapi.com/) · [API key page](https://omdbapi.com/apikey.aspx) · [api-evangelist/omdb](https://github.com/api-evangelist/omdb)
- Data licence is reported as **CC BY-NC 4.0**, so no commercial use on any tier. (verify) [api.market](https://api.market/blog/sleeyax/entertainment/best-movie-apis)
- It is read-only.
- Use: an optional "IMDb 7.8" badge on title detail, fetched lazily by IMDb ID and cached server-side for 7 days or more. It is not used to filter the catalogue, because 1,000 requests a day cannot cover it.

## 4. Trakt — the only realistic writable review target
- REST API v2, with about 150 endpoints. It has OAuth2 (authorization code and device flow). Access tokens last **7 days** and are refreshed with a refresh token. [Trakt OAuth docs](https://docs.trakt.tv/docs/authentication-oauth) · [trakt/trakt-api](https://github.com/trakt/trakt-api) · [api-evangelist/trakt](https://github.com/api-evangelist/trakt)
- Write endpoints relevant to us:
  - `POST /sync/history` to add watches (supports multiple plays and a `watched_at` date, which maps to our stubs).
  - `POST /sync/ratings` for ratings on a 1–10 scale.
  - `POST /checkin` for "watching now".
  - `/scrobble/start|pause|stop` for player integrations.
  - `POST /comments` for comments on movies, shows, seasons and episodes. **Comments must be at least 5 words, and a comment of 200 words or more is auto-flagged as a review.** Spoiler flag, English only, no "via App" text; breaking the rules can get the app blacklisted from commenting. [Trakt comment rules](https://forums.trakt.tv/t/what-are-the-rules-for-posting-comments/22155) · [Apiary: post a comment](https://trakt.docs.apiary.io/reference/comments/comments/post-a-comment) · [issue #407: 429 on comment+rating](https://github.com/trakt/trakt-api/issues/407)
- Rate limits: authenticated GET is about 1,000 calls per 5 minutes. POST, PUT and DELETE are much tighter (about 1 per second). A 429 response comes with `Retry-After`. [Trakt forum: rate limits](https://forums.trakt.tv/t/has-the-trakt-api-rate-limit-changed/40054)
- **2025–2026 business changes (major risk):**
  - Free-user limits came in during Jan/Feb 2025, and VIP went from $30 to $60 a year. [AlternativeTo](https://alternativeto.net/news/2025/2/trakt-tv-has-set-stricter-limits-for-free-users-and-raised-vip-subscription-prices-by-100-/)
  - "Updating Trakt Limits for 2026": free watchlist raised to 250, and watched endpoints paginated after 2026-06-30. [Trakt forums](https://forums.trakt.tv/t/updating-trakt-limits-for-2026/101592) · [discussion #775](https://github.com/trakt/trakt-api/discussions/775)
  - **Free accounts limited to one connected third-party app.** [TROYPOINT](https://troypoint.com/trakt-limits-users-to-one-connection/)
  - **Since about 2026-07-31, API apps owned by free accounts were disabled, and creating an API app requires VIP** ($4.99/month). Staff called it a "temporary anti-abuse measure". [tuliprox #853](https://github.com/euzu/tuliprox/issues/853) · [ETTAYEB](https://ettayeb.fr/en/selfhosted/trakt-api-paywall-selfhosted-media/)
- **Verdict**: Trakt is technically the best outbound sync target, because it takes stubs as plays, ratings, and reviews as comments of 200 words or more. The business risk is real: we pay for VIP, and each user's single free app slot may already be taken. Ship it as **v1**, behind a feature flag and an adapter interface, and never make it the source of truth.

## 5. Simkl
- It has a free developer API with OAuth2 (plus PKCE and PIN flows). The Sync API covers history, ratings and lists (add-to-list). There are no public review or comment writes. [api.simkl.org](https://api.simkl.org/) · [SIMKL/API GitHub](https://github.com/SIMKL/API) · [Simkl FAQ](https://docs.simkl.org/how-to-use-simkl/faq/frequently-asked-questions/what-is-the-simkl-api-and-how-can-developers-utilize-it-for-creating-custom-applications)
- It is a v2 candidate for stub and rating sync, and a fallback if Trakt closes further.

## 6. Letterboxd
- The API is **by request only** (api@letterboxd.com). Letterboxd explicitly does **not** grant access for "private or personal projects", data analysis or recommendations, LLM use, or "any usage that recreates current or planned features of our paid subscription tiers". A competing diary app is unlikely to get access. [Letterboxd API beta](https://letterboxd.com/api-beta/) · [Letterboxd help: API](https://letterboxd.zendesk.com/hc/en-us/articles/15269070369551-Do-you-have-mobile-apps-or-an-API)
- **Letterboxd CSV import is open to users.** Columns include `tmdbID`, `imdbID`, `Title`, `Year`, `Rating` (0.5–5), `Rating10` (1–10), `WatchedDate` (YYYY-MM-DD, which creates a diary entry), `Rewatch` (bool) and `Review`. An export in this format lets users carry their stubs and reviews to Letterboxd themselves. It is also a trust signal ("your data is portable"). [Letterboxd importing data](https://letterboxd.com/about/importing-data/)
- Letterboxd also imports IMDb CSV exports. [Migrating from IMDb](https://letterboxd.com/about/migrating-from-imdb/)

## 7. Where-to-watch
- **TMDB watch/providers** (JustWatch data) is free with TMDB and gives per-region provider lists and logos, with a JustWatch attribution on each item. **Recommended for v1.** [TMDB watch providers](https://developer.themoviedb.org/reference/movie-watch-providers)
- **JustWatch Partner API** is contract-only and aimed at "bigger partners". Not viable. [JustWatch Streaming API](https://www.justwatch.com/us/JustWatch-Streaming-API) · [JustWatch API docs](https://apis.justwatch.com/docs/api/)
- **Watchmode** has a free Developer plan (about 2,500 credits a month, non-commercial, 120 requests per minute) and adds deeplinks and 200+ services. It is a v2 option if we need deeplinks. [Watchmode API](https://api.watchmode.com/) · [request key](https://api.watchmode.com/requestApiKey)

## 9. Gen-Z engagement patterns
- **Discovery is social**: more than 60% of Gen Z often watch titles they first saw as clips on TikTok or Instagram, and 73% of Gen Z fans discover content mainly through social platforms. [CTAM State of Gen Z](https://www.ctam.com/industry-resources/media-behaviors-and-industry-trends/the-state-of-gen-z/) · [Camphouse](https://camphouse.io/news/gen-z-streaming-habits-2025) · [Attest 2026](https://www.askattest.com/blog/research/gen-z-media-consumption)
- They spend less time on long-form: Gen Z watches about 44 minutes less a day of shows and movies than average, and 43% prefer YouTube or TikTok. **Implication**: logging must take 2 taps or fewer, and curation (≥6.5) earns trust with scarce watch time. [Italy Meets Hollywood](https://italymeetshollywood.com/2025/11/43-of-gen-z-prefer-youtube-and-tiktok-to-traditional-tv-and-streaming/)
- **Shareable identity artefacts drive growth**: Spotify Wrapped 2025 was shared more than 500M times (+41% year on year), with 200M engaged users in 24 hours. Hyper-personal, story-sized cards ("listening age") drove the virality. [Meltwater](https://www.meltwater.com/en/blog/spotify-wrapped-listening-age-analysis) · [Wikipedia](https://en.wikipedia.org/wiki/Spotify_Wrapped) · [MIDiA](https://www.midiaresearch.com/blog/overanalysing-our-2025-spotify-wrapped-what-midias-stats-say-about-the-industry)
- **Share cards**: Letterboxd's share-to-Story card is one of its most-used features, and third-party apps exist only to make prettier Letterboxd stories. [Stories for Letterboxd](https://play.google.com/store/apps/details?id=com.heterochromia.storiesforletterboxd) · [scrob #403](https://github.com/ellite/scrob/issues/403)
- **Streaks**: Duolingo reports users are about 3x more likely to return daily with streaks, and that streak repair added about 8% retention. There is a documented backlash against "streak creep". Watching is not a daily habit, so we use **weekly streaks** ("stubbed something 6 weeks running") with a free "intermission" freeze. We should not use daily pressure. [StriveCloud](https://www.strivecloud.io/blog/gamification-examples-boost-user-retention-duolingo) · [The Decision Lab: streak creep](https://thedecisionlab.com/insights/consumer-insights/streak-creep-the-perils-of-too-much-gamification)

## 11. Founder question 1 — "Why a DB, can't it be real-time?" (PM input; Architect decides)
- **User-owned data** (accounts, stubs, reviews, follows) **must** live in our DB. No external API can hold it for us, since IMDb and TMDB cannot store reviews.
- **Catalogue data** could be fetched live from TMDB, but live `discover` calls can't reliably combine our rule (rating ≥ 6.5 **and** vote floor) with stable sorting, pagination beyond 500 pages, search restricted to the curated set, "stub count" joins, and demo mode with no network. A **cached catalogue** (a nightly sync of IDs, ratings and core fields, with detail fields cached on read and a TTL well under TMDB's 6-month cap) gives fast, filterable, join-able pages, and still refreshes ratings daily.
- PM recommendation: a **hybrid**. Cache the curated catalogue index plus fields for lists and sorting in the DB. Fetch rarely-viewed heavy details (full cast, videos, TMDB reviews) live with a short cache. The Architect makes the final call.

## 12. Vote-count floor analysis
- Our rule is `vote_average ≥ 6.5` **on TMDB's scale**, because TMDB is our licensed source. IMDb's rating is shown only as a secondary badge via OMDb.
- Without a floor, TMDB averages on titles with fewer than 50 votes are noise (8.9 averages from 7 votes). TMDB's own Top Rated uses a floor of about 200 for movies. TV titles get fewer TMDB votes, and small fandoms (anime, K-drama) inflate TV averages.
- **Recommendation**: **movies `vote_count ≥ 200`, TV `vote_count ≥ 100`**, both as config (`CATALOG_MIN_VOTES_MOVIE`, `CATALOG_MIN_VOTES_TV`, `CATALOG_MIN_RATING=6.5`). The expected curated size is in the order of **10–15k titles** (verify on first ingest). That is big enough to feel complete for mainstream viewers and small enough for free tiers. Re-evaluate after the first ingest, and flag it if movies fall under 5k or over 25k.
- Hysteresis: a title stays listed if it dips to 6.4–6.5 while it has user stubs, so users' diaries never lose titles. Titles that fall below are hidden from browse but kept reachable by direct URL for existing stub holders.
